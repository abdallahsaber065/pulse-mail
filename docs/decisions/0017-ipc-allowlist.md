# 0017: Per-command IPC allowlist and least-privilege capability

- Status: accepted (2026-10-21, `d75fa4c`)

## Context
Tauri's `core:default` and app commands without an ACL let any script in the
main webview call every command. The webview renders untrusted mail (in a
sandboxed, opaque-origin frame), so the bridge is the most valuable target.

## Decision
- `build.rs` lists every command in `COMMANDS` and passes it to
  `tauri_build::AppManifest::commands`, so Tauri generates an
  `allow-<command>` permission for each and denies anything unlisted.
- `capabilities/default.json` grants only `core:event:allow-listen`,
  `core:event:allow-unlisten` and the explicit `allow-*` list, to the
  `main` window only. No plugin permissions reach JavaScript (clipboard,
  opener and autostart are used from Rust).
- Tests in `security.rs` fail when `COMMANDS`, `generate_handler!` and the
  capability drift apart, when devtools are enabled for release, or when a
  `tracing` call formats a token, body or code.

## Consequences
Adding a command takes three edits (handler, `COMMANDS`, capability); the
test names the missing one. Autogenerated permission files under
`src-tauri/permissions/autogenerated/` are committed.
